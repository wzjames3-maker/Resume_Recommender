# MaxKB 人事招聘工作台 PRD

## 1. 产品定位

本项目以精简后的 MaxKB v2 fork 为多租户知识服务内核，在其中内嵌首个业务模块：人事招聘工作台。当前内核保留用户、工作区、OpenAI 兼容 LLM 与 Embedding、知识库、文档和问答能力；工作流、MCP、工具编排、应用市场及非核心媒体能力已从运行时删除。

招聘工作台不重建认证、工作区、模型管理或知识库。业务数据和 API 均在 `apps/hr` 中实现，遵循 MaxKB 的 Django、DRF、Vue 和工作区隔离模式。

目标用户是同一工作区内的招聘团队。招聘业务不增加 HR、面试官等专用角色，直接继承 MaxKB 既有成员和工作区管理员权限。

## 2. 产品目标

第一期目标是建立可用且可扩展的招聘基础闭环：在一个工作区内维护候选人和职位，并将候选人加入职位的筛选流程。

第一期成功标准：

- 工作区成员可查看候选人、职位和关联指派。
- 成员可新建候选人，并把候选人加入开放职位。
- 工作区管理员可创建、编辑和关闭职位，编辑和归档候选人。
- 所有资源按 `workspace_id` 隔离，跨工作区资源按不存在处理。
- 已关闭职位不能建立新指派；同一候选人和职位不能有重复的有效指派。

## 3. 第一期开关

### 范围内

| 能力 | 说明 |
|---|---|
| 候选人 | 手工维护基本档案、技能、求职意向、来源、备注和归档状态。 |
| 职位 | 维护名称、部门文本、城市、职级、招聘人数、描述和开关状态。 |
| 指派 | 将候选人加入开放职位，记录基础筛选状态和备注。 |
| 管理端 | 人事部菜单，候选人列表/详情、职位列表/详情和指派操作。 |
| 权限 | 复用 MaxKB 成员与工作区管理员身份。 |

### 不在范围内

- 简历上传、文件解析、PII 加密、候选人去重和合并。
- 自然语言搜人、向量检索、模型调用和岗位匹配。
- 面试安排、反馈、Offer、入职和完整招聘状态机。
- 部门组织树、员工档案、考勤、请假、合同与薪酬。
- HR 专用角色、字段级权限和跨工作区协作。

## 4. 用户与权限

| 身份 | 第一期开通的能力 |
|---|---|
| 工作区成员 | 查看候选人、职位和指派；新建候选人；把候选人加入开放职位；推进自己的筛选操作。 |
| 工作区管理员 | 包含成员能力；创建、编辑和关闭职位；编辑和归档候选人；调整任意指派状态。 |

后端必须以 URL 中的 `workspace_id` 过滤每次查询和变更。对象 ID 属于其他工作区时返回统一不存在结果，不返回跨工作区资源的任何字段。

## 5. 业务对象

| 对象 | 关键字段 | 规则 |
|---|---|---|
| Candidate | 姓名、邮箱、手机、当前城市、目标城市、学历、工作年限、技能、来源、备注、状态 | 状态为 `ACTIVE` 或 `ARCHIVED`。归档数据保留以维持历史指派。 |
| Job | 名称、部门文本、城市、职级、招聘人数、描述、状态 | 状态为 `OPEN` 或 `CLOSED`。关闭后不可新建指派。 |
| CandidateAssignment | 候选人、职位、状态、备注、创建人 | 有效状态为 `PENDING_SCREEN` 或 `SCREEN_PASSED`；终态为 `REJECTED` 或 `CLOSED`。同一候选人和职位最多一条有效指派。 |

候选人归档前必须不存在有效指派。职位关闭后保留历史指派，不自动修改其状态。

## 6. 交互流程

1. 成员在候选人页面新建候选人，并填写基本联系与求职信息。
2. 管理员在职位页面创建开放职位。
3. 成员从候选人列表或详情选择“加入职位”，只可选择当前工作区的开放职位。
4. 系统创建 `PENDING_SCREEN` 指派；重复有效指派返回明确的业务错误。
5. 成员在职位详情查看关联候选人并更新筛选结果；管理员可关闭职位或归档无有效指派的候选人。

## 7. 版本路线

| 阶段 | 目标 |
|---|---|
| 第一阶段 | 候选人、职位、指派的基础闭环。 |
| 第二阶段 | 简历上传、结构化解析、去重与候选人检索。 |
| 第三阶段 | 自然语言搜人、岗位匹配和知识库复用。 |
| 第四阶段 | 面试、Offer、入职和招聘流程审计。 |

每个阶段都需要单独规格和验收，不得因后续需求提前引入模型调用、工作流或数据结构。

## 8. 旧版参考的使用边界

`references/agentkb/` 是只读参考快照。其 PRD、FastAPI API、React 页面、独立认证、加密字段和复杂状态机不参与当前运行时。实现可提炼其中的招聘术语、状态迁移规则和测试场景，但本 PRD、当前 MaxKB 代码和各阶段设计规格才是权威来源。
