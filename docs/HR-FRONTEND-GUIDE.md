# 人事部前端使用指导文档

> 适用版本：MaxKB 精简内核 + 人事招聘工作台（apps/hr）
> 本文档描述人事部前端（招聘运营工作台）从登录到日常使用的完整流程。
> 访问入口：管理后台 → 人事部（顶栏「招聘运营」标识旁的主导航）。

---

## 1. 登录与工作区

1. 打开管理后台地址（开发环境 `http://<host>:3000/admin`，生产由部署配置决定），进入登录页。
2. 输入账号密码登录（账号由管理员在「人事成员」中授予 HR 角色后方可进入人事部）。
3. 登录后在右上角确认当前工作区（Workspace）。人事部所有数据按工作区隔离，切换到其他工作区看到的是该工作区独立的候选人/职位/面试数据。

## 2. 角色权限一览

| HR 角色 | 中文 | 主要能力 |
|---|---|---|
| VIEWER | 工作区成员 | 只读查看；联系方式自动打码（138****5678）；可处理分配给自己的「我的面试」 |
| OPERATOR | 招聘运营 | VIEWER + 上传/导入简历、新建候选人、操作 Pipeline 流转、安排/反馈面试、运行 AI 评估、生成沟通草稿 |
| ADMIN | 管理员 | OPERATOR + 新建/编辑/关闭职位、简历库管理、Offer 管理、入职交接、人事成员管理、审计日志、租户注销 |

> 角色在「人事成员」页配置（仅 ADMIN 可操作）。

## 3. 导航结构

顶栏人事部导航分为**主导航**与「更多」下拉（ADMIN 可见）：

- **主导航**：工作台 / Pipeline / 简历库 / 职位 / 面试 / Agent
- **更多（仅 ADMIN）**：Offer 管理 / 简历库管理 / 入职交接 / 人事成员 / 审计日志 / 租户注销

部分子页面通过主页面进入（如 批量上传简历、简历语义检索、我的面试、候选人详情、新建职位）。

## 4. 页面与操作流程

### 4.1 工作台（/hr/dashboard）

招聘运营入口页，用于快速开始：

- **快捷入口**：批量上传简历、新建职位、语义检索、面试管理、Agent 工作台。
- **关键指标**：我负责的候选人、开放职位、我的面试、待补反馈（含逾期条数）。
- **Agent 采纳率卡**：默认折叠，展开可查看各 Agent 的采纳率统计。

### 4.2 Pipeline（/hr/pipeline）

以「申请」为中心的候选人阶段流转页。

**操作流程：**
1. 顶部选择职位（不选则展示空态提示）。
2. 看板按流程阶段分列展示该职位的所有申请卡片。
3. **拖拽卡片**到目标阶段完成流转（向后回退阶段会弹出原因收集框，填写后确认）。
4. 卡片上可查看候选人、当前阶段、来源、负责人、AI 提案状态。
5. 顶部筛选：搜索（姓名/电话/邮箱）、状态（在途/已录用/已淘汰/全部）。
6. 管理员可点「新建职位」跳转开职位。

> 所有阶段变更都会写入审计记录（ApplicationEvent 不可变账本），可在候选人详情时间线查看。

### 4.3 简历数据库（/hr/candidates，多库总览）

简历库首页，管理多个简历库：

- **概览条**：有效简历库数、总库简历数、业务库数、待解析数。
- **库卡片**：每个库显示 简历数/候选人数/待解析；点击卡片进入**该库内的候选人页面**（`/hr/resumes/databases/:databaseId`）。
- 头部操作：库管理（ADMIN）、语义检索、批量上传简历。

> 总库为系统库（服务端强制，无法归档）；业务库可多选归档。

### 4.4 库内候选人 / 全部候选人（/hr/candidates/list）

候选人档案列表页，是日常处理简历的主战场。

**筛选**：姓名、城市、技能、年限区间、学历、来源、简历库（跨库视图下）、状态（在库/已归档）、「待我处理」。
**AI 搜索**（OPERATOR+）：输入自然语言如「找 3 年以上 Python 经验在上海的人」直接语义检索。
**列表操作**：姓名（合规缺失标记「合规待补」）、城市、学历/年限、技能标签、来源、负责人、AI 提案列。
**头部操作**：
- 「导入候选人」下拉：上传简历（docx/txt）/ CSV 批量导入（ADMIN）。
- 库管理（ADMIN）、AI 设置（ADMIN）、库内检索、导出（ADMIN）、新建候选人（OPERATOR+）。
- 行内更多：查看详情、编辑、归档/恢复、合并、删除。

### 4.5 候选人详情（/hr/candidates/:id）

- 档案信息：联系方式（VIEWER 打码）、技能、来源、负责人、合规信息（告知状态/版本、联系偏好等，收在「系统与合规信息」折叠区内）。
- 简历与解析状态、数据流转日志。
- **时间线**：该候选人所有申请的阶段流转、面试、Offer、Agent 提案等事件。
- 可从此进入 Pipeline、安排面试、发起 Offer（视权限与阶段）。

### 4.6 批量上传简历（/hr/resumes/upload）

**流程：**
1. 拖拽或点击选择文件（支持 **DOC / DOCX / TXT**，单次最多 **100 份**）。
2. 右侧「导入设置」选择**目标简历库**（可多选）：**总库默认勾选且不可取消**（强制入总库），业务库手动多选。
3. 点击上传。系统自动去重（相同内容 SHA-256 校验，重复文件标记且不覆盖）、解析文本、抽取信息、自动建档候选人并向量化入库。
4. 上传后回到候选人列表，新简历状态为「等待解析」→ 自动变为「解析成功」；失败显示错误原因。

> 若一直停留在「等待解析」，说明解析 Worker（Celery）未运行，请联系运维启动。

### 4.7 简历库管理（/hr/resumes/databases，ADMIN）

- 概览：有效库数、总库简历、业务库简历归属、待解析。
- 表格列出全部库（名称/说明/状态/简历数/候选人数/待解析/创建时间）。
- **新建简历库**：填写名称与说明。
- **归档**：仅业务库可归档；总库为系统库不可归档。

### 4.8 简历语义检索（/hr/search）

基于简历知识库的语义召回 + RRF 融合 + Rerank 精排：

1. 输入自然语言（如「有幕墙系统设计经验、3 年以上 Python 后端」）。
2. 可选限定**简历库范围**（多选，默认全部）。
3. 默认只显示基础检索；点「高级选项」可展开 模式（自动/混合/向量/整句/技能）与 TopK。
4. 结果按相关度排序，展开行可看**命中段落原文**与分数；分数拆解、检索元信息在高级选项展开后可见。
5. 结果行可进入候选人详情。

### 4.9 职位（/hr/jobs）

职位维护页：

- 筛选：名称、状态、待我处理；重置。
- 列表：职位名、部门/城市、职级、招聘人数、状态、负责人、操作。
- 展开行：该职位的**候选人列表**（当前阶段/来源/负责人/AI 提案），可「前往 Pipeline」做阶段流转。
- 操作（按权限）：
  - **编辑**（ADMIN）：打开编辑弹窗，可改名称/部门/城市/职级/人数/状态/负责人/描述/技能要求；支持「AI 起草 JD」「AI 抽取技能」。
  - **AI 找人才**（OPERATOR+）：Sourcing 人才库激活，生成候选激活清单。
  - **恢复 / 关闭**（ADMIN）：关闭前预览影响（STRICT/BULK 两种模式），需填关闭原因；已关闭职位不可再编辑状态。

### 4.10 新建职位（/hr/jobs/new）

- 填写最小信息：职位名称（必填）、部门、城市、职级、招聘人数、状态、负责人、职位描述（必填）、技能要求（逗号分隔，可 AI 抽取）。
- 保存后系统自动为该职位创建默认流程阶段（待筛选→初筛通过→面试中→Offer）。

### 4.11 面试管理（/hr/interviews）

全局面试列表（OPERATOR+ 可见）：

- 筛选：状态、关键词（候选人/职位/面试官）、逾期。
- 列出候选人、职位、轮次、面试官、日程、反馈截止与文本。
- 可查看/编辑面试、提交反馈。

### 4.12 我的面试（/hr/my-interviews）

面试官本人视角（登录即可访问，无需 HR 角色）：

- 列出分配给我的面试，支持提交反馈。
- 面试官可点「AI 生成草稿」用 Interview Copilot 生成面试题/评估草稿（**草稿不自动提交**，需人工确认后写入）。

### 4.13 Agent 工作台（/hr/agents）

集中查看受控 Copilot 的运行情况（**所有写入仍需人工确认，Propose → Confirm → Execute**）：

- **运行概览**：按 Agent 类型展示 运行数/成功/失败/跳过、提案总数/已决/采纳率。
- **运行记录**：筛选 Agent 类型/状态/日期；查看每次运行的输入输出、工具轨迹、Token、耗时、证据链（可打开简历原文段落抽屉）。
- **Proposal 收件箱**：待处理提案列表，点开看详情 → 采纳执行或忽略（视角色权限）。

支持的五类 Agent：

| Agent | 用途 | 产出 |
|---|---|---|
| SCREENING | 候选人初筛评估 | ADVANCE / HOLD / REJECT 建议 + 证据 |
| JD_DRAFT | 职位描述起草 | JD 草稿（采纳写入职位字段，需 ADMIN） |
| INTERVIEW_COPILOT | 面试助手 | 面试题准备 / 反馈评估草稿 |
| SOURCING | 人才库激活 | 沉睡候选人激活清单 |
| COMMUNICATION_DRAFT | 沟通话术 | 淘汰/推进/FAQ 等话术草稿 |

Agent 入口散落在对应业务页（职位页筛选/JD、候选人 AI 评估、我的面试 Interview Copilot、职位 AI 找人才、候选人沟通草稿），工作台统一查看与处理。

### 4.14 Offer 管理（/hr/offers，ADMIN）

- 统一查看工作区 Offer：候选人、职位、版本、状态、薪资、审批/发送状态。
- 状态流转：草稿 → 审批 → 发送 → 接受/拒绝/撤回；候选人接受 Offer 后对应申请自动进入 HIRED。

### 4.15 入职交接（/hr/handoffs，ADMIN）

- 查看 Offer 接受后的入职交接清单与执行状态。
- 失败的交接项可「重试」；交接配置在「入职交接」页设置（审批人、待办项等）。

### 4.16 人事成员（/hr/access，ADMIN）

管理本工作区 HR 角色：

- 列表展示系统成员及其 HR 角色（无角色显示「工作区成员」）。
- 为成员**授予 / 修改 / 移除**角色（ADMIN / OPERATOR / VIEWER）。
- 所有授权变更写入审计日志。

### 4.17 审计日志（/hr/audit-logs，ADMIN）

- 按用户、动作类型、对象类型、时间段筛选全部操作日志。
- 覆盖：创建/修改/归档/删除、阶段流转、职位关闭、Offer 操作、授权变更、Agent 运行与决策、租户注销等。

### 4.18 租户注销（/hr/offboarding，管理员入口）

> 高风险操作，谨慎使用。

- **预览**：dry-run 展示将清理的数据与存储文件。
- **导出返还包**：导出脱敏数据返还包（手机号/邮箱已脱敏）。
- **确认注销**：需输入工作区 ID 确认；存在活跃申请/运行中 Agent/未关闭职位时被守卫拦截（需先处理或 Force）。
- 注销后仅保留 hr_offboard tombstone 留痕，支持幂等重入。

## 5. 端到端典型场景

### 场景 A：简历入库（最常用）

1. 工作台 →「批量上传简历」（或 简历库 → 批量上传）。
2. 拖入 docx/txt 文件（最多 100 份），勾选目标库（总库默认选中）。
3. 上传 → 等待解析 → 状态变「解析成功」。
4. 到简历库点击对应库进入候选人列表查看新档案；重复简历自动标记不重复建档。

### 场景 B：开职位 → 筛候选人 → 推进 Pipeline

1. 职位页 →「新建职位」，填好职位描述与技能 → 保存（自动建默认阶段）。
2. （可选）ADMIN 在职位页点「AI 起草 JD」让 Agent 生成草稿，采纳后写入。
3. 候选人入库后，在职位展开行或 Pipeline 选中职位查看申请。
4. 拖拽卡片跨阶段流转；回退阶段需填写原因。
5. 每步在候选人详情「时间线」留痕。

### 场景 C：面试 → Offer → 入职

1. Pipeline 中候选人进入「面试中」阶段后，点卡片「面试」安排面试（选面试官、时间、反馈截止）。
2. 面试官在「我的面试」提交反馈（可用 Interview Copilot 生成草稿后确认）。
3. 候选人到 Offer 阶段后（ADMIN）发起 Offer，走 审批 → 发送。
4. 候选人接受后申请自动 HIRED，进入「入职交接」清单，按配置执行待办，失败项可重试。

### 场景 D：AI 辅助（受控 Copilot）

所有 Agent 只**提建议不直接改数据**，人工确认后执行：

1. **初筛**：候选人 AI 评估（Screening）→ 看证据 → 采纳 ADVANCE/HOLD/REJECT。
2. **JD**：职位编辑「AI 起草 JD」→ 采纳（ADMIN）写入职位。
3. **找人才**：职位页「AI 找人才」（Sourcing）→ 生成激活清单 → 按清单联系。
4. **沟通**：候选人「生成沟通草稿」（淘汰/推进等）→ 确认后复制使用。
5. 所有运行与决策在「Agent 工作台」集中查看、重试失败运行。

### 场景 E：多库管理

1. 简历库页 →「库管理」新建业务库（如「2026 春招-后端」）。
2. 上传简历时勾选 总库 + 对应业务库 → 简历同时归属多个库。
3. 总库始终收录全部简历（服务端强制），业务库可按项目/批次归档。
4. 检索时可按库范围限定召回。

## 6. 核心机制说明

- **总库强制 + 业务库多选**：每次上传，总库在前端默认勾选且服务端强制加入；业务库手动多选；同一份简历（去重后）可同时属于多个库。
- **简历去重**：按内容 SHA-256 在工作区内去重，重复上传不覆盖、不重复建档。
- **解析流水线**：上传 → 提取文本 → 解析字段 → 建档候选人 → 清洗 → 切片 → 向量化（异步执行，Worker 空闲时自动完成）。
- **受控 Agent**：所有 AI 产出为 Proposal（建议），人工采纳后才会调用写接口执行；运行失败可重试，不影响业务数据。
- **合规脱敏**：VIEWER 角色查看联系方式自动打码；数据流转日志中未脱敏全文仅 OPERATOR+ 可读。
- **审计留痕**：阶段流转、职位关闭、授权、Offer、Agent 决策等全部写入审计日志与不可变事件账本。

## 7. 常见问题（FAQ）

| 现象 | 原因/处理 |
|---|---|
| 简历一直「等待解析」 | 解析 Worker（Celery）未运行，联系运维执行 `python main.py dev celery` |
| 负责人/面试官显示 UUID | 旧版本成员数据源问题，已修复为 HR 成员接口；刷新即可 |
| 上传时总库不可取消勾选 | 设计如此：总库为系统库，服务端强制加入 |
| 职位状态选择被禁用 | 该职位已关闭（CLOSED）；需先「恢复」再编辑 |
| 候选人联系方式打码 | 当前账号为 VIEWER 角色，需 OPERATOR/ADMIN 才可见完整信息 |
| Pipeline 看不到某候选人 | 请确认顶部已选择职位，且候选人属于该职位的申请 |
| 「更多」菜单里没有 Offer/人事成员等 | 当前账号不是 ADMIN |
| Agent 提案无法采纳写入 | 部分写入（如 JD 采纳、Offer）需 ADMIN 角色 |
