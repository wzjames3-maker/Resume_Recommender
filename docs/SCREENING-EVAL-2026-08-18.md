# Screening 真实模型评测（2026-08-18，数据库恢复后复测）

> 环境：PostgreSQL/Redis/MinIO 原容器恢复后，在 eval-ws 评测语料（300 候选人 / 4 职位 / 300 简历，历史运行 512 次）上复跑真实 Screening。
> 与 2026-08-17 基线同 seed 7、同 200 例构造，结果可对比。

## 1. 执行

```bash
RUN_REAL_MODEL=1 uv run python manage.py eval_screening \
  --workspace eval-ws --limit 200 --seed 7 \
  --report logs/screening_eval_200_2026-08-18.json
```

- 配对：200 例（正 100 / 负 100），正样本完整 JD 构造、负样本无关技能
- 模型：sensenova-6.8-flash-lite（数据库凭据，SUCCESS）
- 总耗时：1396s；平均 6.98s/例

## 3. 结论

- 宽松一致率 82% **复现达成 ≥80% 目标**（正 64% / 负 100%）。
- 严格一致率从 55% 提升到 82%：ADVANCE 12 例 → 5 例，60-79 分带全部 HOLD 人工复核，符合 HOLD 分带默认 48-59 改人工复核的设计意图。
- 残留误拒（正 36%）仍是 flash-lite 数值标定问题（清晰匹配评 0-47 分但评论文本说一致），彻底解决需更强模型档位对比。
- 评测构造与模型链路在容器恢复后完整可复现，运行账本新增 200 条。
