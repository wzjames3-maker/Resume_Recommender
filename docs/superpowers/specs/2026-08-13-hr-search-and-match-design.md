# 候选人组合搜索与职位匹配设计

## 目标

在 `apps/hr` 交付候选人高级组合搜索与职位匹配建议，帮助招聘人员按条件定位候选人并基于职位技能要求获得推荐。搜索与匹配均为确定性规则（数据库查询 + 技能交集评分），不调用 LLM；自然语言意图解析与知识库复用留到第四期。

## 范围

### 范围内

- `Job` 增加 `skill_requirements`（技能要求列表，JSON 数组），由管理员维护。
- 候选人列表支持组合过滤：姓名、城市、状态、多技能（AND 语义）、最高学历、工作年限区间、来源渠道。
- 职位匹配接口：给定开放职位，按候选人与职位技能要求交集、城市匹配计算匹配分数，返回匹配候选人分页列表。
- 前端：职位表单增加技能要求编辑；职位展开区展示匹配候选人，可一键加入职位。
- 匹配结果中的候选人可走既有 `create_assignment` 建立指派。

### 不在范围内

- 自然语言查询解析（"5 年 Java 后端"）与 LLM 意图路由。
- 职位描述自动抽取技能要求（保持人工维护）。
- 候选人画像、排序学习、知识库检索复用。
- 异步批量匹配。

## 数据模型

### Job 扩展

在现有 `Job` 增加：

- `skill_requirements`：`JSONField(default=list)`，职位技能要求列表，元素为非空字符串。
- 一期已有字段不变；新建或编辑职位时由管理员填写技能要求。

## 匹配规则

### 候选人过滤（高级搜索）

`page_candidates` 在现有 `name` / `city` / `status` 基础上增加：

| 参数 | 规则 |
|---|---|
| `skills` | 逗号分隔多个技能，全部命中才返回（AND 语义），忽略空片段。 |
| `highest_degree` | 精确匹配最高学历（博士/硕士/本科/大专/中专/高中）。 |
| `years_min` / `years_max` | 工作年限区间过滤，`years_experience` 为空不命中区间条件。 |
| `source` | 精确匹配来源渠道。 |

### 职位匹配

`GET /jobs/{job_id}/matches`，返回候选人与职位匹配结果：

- 只匹配 `ACTIVE` 候选人，职位须为当前工作区开放职位。
- 匹配分数（整数，满分 10 分）：
  - 技能命中：每个命中技能 +2 分，最高 +8 分。
  - 城市匹配：候选人 `current_city` 或 `target_city` 等于职位 `city`（职位城市非空时）+2 分。
- 命中技能列表随结果返回，用于前端展示匹配依据。
- 分页返回，按匹配分数降序。
- 无技能要求且无城市时返回空列表（不推荐）。

### 一键加入职位

前端从匹配结果调用既有 `POST /jobs/{job_id}/assignments`（`candidate_id` + 备注），沿用有效指派唯一约束。

## API

统一前缀：`/admin/api/workspace/{workspace_id}/hr`。

| 方法 | 路径 | 用途 | 最低权限 |
|---|---|---|---|
| GET | `/candidates/{page}/{page_size}` | 分页候选人与高级组合过滤 | 成员 |
| GET | `/jobs/{job_id}/matches/{page}/{page_size}` | 职位匹配候选人分页列表 | 成员 |
| POST | `/jobs/{job_id}/assignments` | 一键加入职位（沿用一期） | 成员 |

匹配响应每项：`candidate_id`、`name`、`current_city`、`target_city`、`years_experience`、`skills`、`match_score`、`matched_skills`。

跨工作区职位匹配返回 404；关闭职位返回 400。

## 前端

- 候选人检索区增加：最高学历、工作年限区间（最小/最大）、来源渠道（已有）。
- 职位创建/编辑对话框增加「技能要求」输入（逗号分隔，保存为数组）。
- 职位行展开区增加「匹配候选人」区域：展示匹配分数与命中技能，提供「加入职位」按钮，成功后刷新匹配列表与指派数。
- 候选人列表技能筛选用逗号分隔多值，全部命中。

## 测试

后端测试至少覆盖：

- 高级搜索：多技能 AND、学历精确匹配、年限区间、来源过滤、无技能候选人被区间条件排除。
- 匹配：技能命中加分、城市加分、无技能/无城市返回空、分数排序、关闭职位拒绝、跨工作区 404。
- `skill_requirements` 序列化与校验（非字符串元素拒绝）。
- 一键加入职位沿用既有去重与关闭校验（回归）。

验收命令沿用前两期：HR 全量测试、Django 检查、迁移漂移检查、前端类型检查与双构建、裁剪端点产物扫描。

## 取舍

- 人工维护职位技能要求优先于从职位描述自动抽取：确定性高、零模型成本，描述抽取留待四期 LLM 阶段。
- 组合搜索为确定性数据库过滤，不引入检索索引；数据量增长后再评估 pgvector 或全文索引。
- 匹配分数采用简单线性规则，不引入学习排序。
