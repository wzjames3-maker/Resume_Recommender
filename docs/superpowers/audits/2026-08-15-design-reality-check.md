> 结论（v2 修订）：**质疑成立**。但"真实数据形态"需按 PRD 定义——产品输入格式已锁定为 **docx/txt**（PRD §4.1：`简历上传、docx/txt 规则解析`），**无图片/OCR 需求**。数据集的 OCR 分号流是天池训练数据形态，不代表业务输入。真实风险是 docx 排版多样性（表格/样式/软换行）与提取保真。

### 1.3 合成 vs 真实对照

| 维度 | 合成（实验用） | 数据集原文（非业务输入） | 业务真实输入（docx/txt） |
|---|---|---|---|
| 结构 | 【教育经历】+ `- ` 条目 + 换行 | 分号流连续文本，字段名内嵌 | **人排版**：有换行；常见表格布局、样式标题、无标题纯段落 |
| PII | 手工 strip 电话 | 电话/邮箱在原文 | 简历含电话/邮箱（必须清洗） |
| 噪声 | 无 | OCR 错字、脏值 | 无 OCR 错字；有排版怪癖（软换行、空段、制表符） |
| 提取风险 | — | — | 表格排版已确认不存在（产品决策 2026-08-15）；余下：软换行/样式标题（变体评测覆盖） |

## 2. 方案逐层判决

| 层 | 原假设 | 按 PRD 输入（docx/txt）检验 | 判决 |
|---|---|---|---|
| L0 文本提取 | python-docx 段落 | **已确认不考虑表格**（产品决策：业务简历无表格排版） | ✅ 现状实现够用 |
| L1 行号边界标注 | 文本有行 | docx 按段落提取/txt 按行——**有行** | ✅ 行号协议恢复成立 |
| 条目级粒度 | 【】+`-` 边界 | 人排版：表格行、样式标题、无标题段落 | ✅ 概念成立，docx 样本重验 |
| PII 清洗 | 已 strip | 真实简历含电话/邮箱 | ❌ 多层防御（保留） |
| rerank 补偿 | 交叉编码器原理 | 与输入格式无关 | ✅ 方向对，样本需扩大 |
| 成本 80% 免 LLM | 结构占比假设 | 全量简历过 LLM 切片 | ❌ 按全量重估 |
| 分号流兜底 | （v3 无此项） | 业务不出现分号流，但数据集可作**压力测试** | ⚠️ 降级路径覆盖即可 |

## 3. 仍然成立的

1. **LLM 主干**：分号流/OCR 噪声下，LLM 是唯一能读字段结构做语义分段的方法；
2. **禁止改写、原文保真**：OCR 文本原样入索引，引用展示原文；
3. **校验修复层**：拼接==原文硬校验，在无结构文本上更重要；
4. **rerank 精排方向**：交叉编码器优于双塔是通用结论，与数据形态无关。
