# 问题定义

## 背景现象

企业 HR 在招聘过程中，面对大量历史简历库（通常 10 万份以上），筛选候选人主要依赖关键词搜索或人工逐份阅读。当前流程为：

`
HR 收到招聘需求
    ↓
人工筛选简历 / 关键词搜索人才库
    ↓
初步匹配候选人
    ↓
推荐给业务部门
`

这一过程存在以下问题：
- 关键词搜索无法理解语义（如搜"Java 工程师"会遗漏"Spring Boot 后端开发"）
- 人工筛选耗时巨大，HR 首轮筛选占据整个招聘周期的大量时间
- 推荐结果缺乏可解释性，HR 难以向业务部门说明推荐理由
- 多轮追问（如"再推荐几个"、"女生呢"、"学历高一点"）无法被系统理解，每次都要重新构造查询

## 核心问题

企业人才库中大量简历无法被高效、语义化地检索和推荐，HR 筛选效率低、推荐质量不可控。

## 影响范围

- **受影响角色**：HR、技术招聘专员（Tech Recruiter）、用人部门负责人（Hiring Manager）
- **频率**：每个招聘需求都会触发简历筛选，高频场景
- **严重程度**：中大型企业人才库 10 万+ 份简历，首轮筛选时间占招聘周期 40%-60%

## 不解决会怎样

- HR 持续依赖低效的关键词搜索，优秀候选人被遗漏
- 招聘周期拉长，关键岗位空缺成本持续增加
- 推荐结果缺乏数据支撑和可解释性，HR 与业务部门沟通效率低
- 人才库沦为"数据坟场"，历史简历积累无法产生价值

## 解决后预期

- HR 通过自然语言描述招聘需求，系统自动理解意图并召回匹配候选人
- 支持多轮对话式追问（如"再推荐几个"、"学历高一点"、"不要外包"）
- 推荐结果包含评分、推荐理由、匹配技能、缺失技能等可解释信息
- Top-10 候选人的人工采纳率达到 80% 以上
- HR 首轮筛选时间减少 70%
- 系统通过 API 与现有 ATS / HR 系统集成，不替代现有系统

## 明确不做的事（V1 边界）

V1 聚焦于**人才检索与推荐**，以下功能明确不做：

| 不做项 | 说明 |
|--------|------|
| JD 创建 | 不负责生成或管理职位描述 |
| 面试安排 | 不涉及面试调度和日历管理 |
| Offer 管理 | 不涉及薪酬谈判和 Offer 流程 |
| 候选人沟通 | 不负责与候选人的邮件/消息交互 |
| ATS 全流程管理 | 不替代现有 ATS，仅作为 AI 检索推荐层 |
| SaaS 多租户 | V1 为单企业内部部署，不做多租户架构 |
| 实时简历抓取 | 不做从 Boss/猎聘等平台的实时数据抓取 |

## 业务目标（Business Goals）

| 目标 | 度量指标 |
|------|----------|
| 提升 HR 筛选效率 | 首轮筛选时间减少 70% |
| 提升推荐质量 | Top-10 候选人人工采纳率 ≥ 80% |
| 支持自然语言交互 | HR 无需学习复杂检索语法 |
| 保证推荐可解释性 | 每条推荐附带评分 + 理由 + 技能匹配分析 |

## 系统定位

- **产品形态**：企业内部智能招聘助手（Enterprise AI Recruiting Assistant）
- **部署方式**：单企业内部部署（On-Premise），V1 不做多租户
- **集成方式**：独立服务架构，通过 API 与现有 ATS / HR 系统集成
- **介入环节**：招聘流程中的筛选与推荐阶段

## 系统边界（架构层）

V1 作为 AI 检索与推荐层，假设企业已有历史简历库，采用独立服务架构：

`
Resume Parser → Resume Store → Vector Index → Agent Router → Recommendation Engine
`

通过 API 与现有 ATS 或 HR 系统对接，不替代 ATS 本身。

## 数据规模预估

| 维度 | V1 目标 | 扩展目标 |
|------|---------|----------|
| 简历数量 | 10 万份 | 100 万份+ |
| 简历格式 | PDF / DOCX / 图片 OCR / JSON | + Boss 导出 / 猎聘 / LinkedIn |
| 简历平均长度 | 2-5 页 | - |
| Chunk 策略 | 按语义段落切分（教育/工作/项目/技能） | - |
