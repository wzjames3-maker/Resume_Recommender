## 实现要求

### 候选人卡片 CandidateCard
1. 展示字段：姓名、头像（占位）、当前职位、工作年限、技能标签、匹配度评分
2. 技能标签以彩色 tag 形式展示（最多显示 5 个，超出显示 `+N`）
3. 匹配度评分以进度条或星级展示
4. 点击卡片展开详情：触发 Lazy Load 按需加载推荐理由（调用 /api/v1/chat reason_lazy 事件），展示工作经历、教育背景、项目经验
   - 默认折叠状态只展示 Score Breakdown（无需 LLM，零延迟）
   - 展开时显示 loading 状态，后端返回理由后渲染
   - 已加载的理由在本轮对话内缓存，重复展开不重新请求
5. 支持「查看详情」按钮跳转到候选人详情页或弹窗
6. 卡片数据结构：默认接收 {name, score, score_breakdown, matched_skills, missing_skills}；reason 字段初始为空列表，展开时 Lazy Load 填充
7. 并发防护：前端组件维护 is_loading 状态锁，展开触发请求时锁定，防止同一卡片理由的并发重复请求；请求完成后解锁

### 筛选标签 FilterTags
1. 展示当前对话中识别到的筛选条件（从 Chat API `sources` 事件提取）
2. 支持点击标签移除筛选条件
3. 支持手动添加筛选标签
4. 标签变更后自动触发新的搜索请求

### 简历上传 UploadModal
1. 使用 `st.dialog` 或 `st.expander` 实现弹窗/展开面板
2. 文件拖拽上传区域
3. 支持 `.pdf`, `.docx`, `.doc` 文件
4. 上传进度指示
5. 上传成功后显示解析结果摘要
6. 调用 `/api/v1/resumes/upload` 端点

### 侧边栏 Sidebar
1. 对话列表：展示用户的所有对话，按最近更新排序
2. 新建对话按钮
3. 点击对话切换到对应对话历史
4. 用户信息展示（用户名、角色）
5. 退出登录按钮
6. 调用对话管理 API（T-033 产出）
