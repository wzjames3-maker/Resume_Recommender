# T-039: 用户完整流程端到端测试

## 基本信息
- **对应 Spec**: integration-testing（E2E 全流程）
- **对应 AC**: 全流程端到端验证
- **依赖任务**: T-035（候选人卡片 + 侧边栏 + 上传）
- **预计工时**: 1.5 天
- **优先级**: P0

## 输入
- T-035 产出的完整 Streamlit 前端应用
- 所有 Phase 2 产出的 API 端点（Chat、Upload、Login、Conversations）
- E2E 测试场景定义

## 输出
- `tests/e2e/test_full_flow.py` — E2E 测试文件（使用 `playwright` 或 `streamlit-testing`）
- `tests/e2e/conftest.py` — E2E 测试配置（浏览器配置、页面对象）
- E2E 测试运行报告

## 实现要求

### 测试场景：用户完整旅程
```
1. 打开应用 → 看到登录页
2. 输入错误密码 → 显示错误提示
3. 输入正确密码 → 进入聊天主界面
4. 在聊天框输入"找一个3年经验的Python开发"
5. 看到流式回复 + 候选人卡片
6. 点击候选人卡片 → 查看详情
7. 在侧边栏点击"新建对话"
8. 上传一份 PDF 简历 → 显示解析结果
9. 在侧边栏切换回第一个对话 → 历史消息仍在
10. 退出登录 → 回到登录页
```

### 测试用例设计
1. **完整旅程**: 按上述 10 步执行，每步有断言
2. **登录异常**: 连续 3 次错误密码 → 验证是否有锁定或限流
3. **并发对话**: 快速切换多个对话 → 消息不串
4. **上传 + 搜索**: 上传简历后立即搜索 → 验证新简历可被检索
5. **Token 过期**: 模拟 token 过期 → 自动跳转登录页
6. **网络异常**: 模拟后端不可用 → 前端显示友好错误提示

### 技术方案
- 优先使用 `playwright` 进行浏览器级 E2E 测试
- 备选：`streamlit-testing` 库进行组件级测试
- 使用 `pytest` 组织测试，`conftest.py` 管理浏览器生命周期
- 测试在 Docker Compose 环境中运行（前端 + 后端 + DB）
