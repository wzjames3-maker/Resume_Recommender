# 简历解析质量评测规范

> 版本：v0.4
> 日期：2026-08-07
> 状态：草案，待审查
> 关联：PRD F6、M3；MVP 范围与验收 spec §3.1；简历 Schema 与导入模板 spec。
> 本 spec 定义「简历解析质量」的可复现评测方法，是 MVP 核心目标之一（解析质量）的验收依据。
> v0.4 变更（本轮 review 修复）：①流水线失败样本以全字段 `null` 计入端到端 F1，禁止通过 `failed` 排除难样本；②补充字段清单、skills 集合、数组配对 tie-break 与 `null/[]` 矩阵；③按类别冻结成功率门槛，防止选择性失败；④补充 evidence 状态、幻觉阻断规则和 conflict 零分母；⑤明确源文件格式转换产物与 holdout 版本关系。
> v0.3 变更（review 修复）：①冻结样本与查询配额（含正交维度与最低数量）；②字段级 F1 定义可执行原子单位与 TP/FP/FN 聚合规则；③失败样本计入口径与 IR 阈值冻结；④manifest 扩展为版本化评测 bundle（GT/fixture/画像标注集/运行配置哈希）；⑤conflict 排除集改为以 Ground Truth 冻结为准，并新增 conflict 检测准确率；⑥长文本 bigram 改为多重集合；⑦画像准确率明确为参考观测指标。
> v0.2 变更：新增评测 manifest（§2.5）、字段归一化与匹配规则（§3）、画像标注协议（§4.4），使指标可复现、可自动计算。

## 1. 评测目标

验证简历解析流水线（双通道抽取 → Markdown IR → 两阶段 LLM 结构化 → 人才画像）能否：

- 准确抽取结构化字段，不编造、不遗漏。
- 对无法确定的字段输出 `null`，不猜测。
- 对脏数据（字段矛盾、时间线混乱）保持健壮。

## 2. 数据来源

### 2.1 数据集

- **名称**：简历信息抽取数据（飞桨 AI Studio 星河社区公开数据集）。
- **来源**：https://aistudio.baidu.com/dataset/detail/40148/file
- **用途**：仅作为评测样本来源，不进入生产数据。
- **许可与版本**：数据集页面声明的许可与文件列表以下载快照为准；文档不复制原始简历内容。

### 2.2 样本集构建

评测样本集从数据集中抽取并脱敏，覆盖四类版面样本（与 PRD F6 一致）：

| 类别 | 覆盖场景 | 最低数量 |
|------|----------|----------|
| 表格型 | 表格为主流的简历版面 | ≥ 50 |
| 文本框型 | 文本框 / 分栏排版 | ≥ 50 |
| .doc / docx 文档型 | 段落式简历 | ≥ 50 |
| 脏数据 | 字段矛盾、时间线混乱、信息缺失 | ≥ 50 |

> **正交维度标记（正式冻结）**：每份样本标记 `format`（doc / docx / txt）、`layout`（表格型 / 文本框型 / 段落型）、`quality_flags`（正常 / 字段矛盾 / 时间线混乱 / 信息缺失，可多选）；`category` 仅为兼容展示的主标签，不参与可评分分组。`category` 与 `quality_flags` 解耦——「表格型 + 字段矛盾」「文本框型 + 信息缺失」等组合分别统计，避免版面维度与数据质量维度混淆。
>
> **配额预注册（在实现前、构建 manifest 时一次性冻结）**：
> - 每种 `format` 至少 20 份；每种 `layout` 至少 40 份；每个原子 `quality_flags`（字段矛盾 / 时间线混乱 / 信息缺失）至少 30 份；`正常`样本也必须有明确数量。多个 flag 的组合不重复计入最低配额。
> - 整体样本量 ≥ 200；去除重复 / 近重复样本（按内容相似度去重）。
> - `split` 只能为 `dev` / `holdout` / `eval`；预留独立 holdout 子集（≥ 20%），不参与解析器或提示词调参，仅用于最终验收；最终门槛只在 holdout 上确认，`dev` 不得进入最终报告。
> - 每类（format / layout / quality_flags）分别报告指标，整体通过不豁免任一类别未达标（见 §4.6）。

### 2.3 标准答案（Ground Truth）标注

每份样本简历配一份标准答案 JSON，结构与简历 Schema spec 一致：

```json
{
  "name": "张三",
  "gender": "男",
  "highest_degree": "本科",
  "city": "杭州",
  "expected_city": "杭州",
  "skills": ["Java", "Spring"],
  "education": [
    {"school": "H 大学", "degree": "本科", "major": "计算机", "start": "2013-09", "end": "2017-06"}
  ],
  "work": [
    {"company": "A 公司", "title": "后端工程师", "content": "负责支付系统", "start": "2017-07", "end": "2021-06"}
  ]
}
```

- 标准答案由人工标注，标注人需遵循统一的字段判定规则（见 2.4）。
- 标注结果独立于解析实现，作为评测基准。
- Ground Truth 顶层字段清单固定为 Schema §1.1、§1.2、§1.3、§1.4、§1.8 中的可评分字段；`import_summary` 不计入解析 F1。
- 示例中未展开的字段（如 `work[].type`、`years_experience`、可选基本信息）在正式 Ground Truth 文件中必须显式写入值或 `null`，不得通过字段缺失改变评分。

### 2.4 字段判定规则（标注用）

- 简历中明确出现的字段 → 标注实际值。
- 简历中未出现 / 无法确定 → 标注 `null`；`unknown` 不作为字段取值（见 Schema spec §1 空值语义）。
- 字段间矛盾 → 由**标注方**（Ground Truth）判定并标注 `conflict`（含双方原始值、evidence，见 Schema spec §1.7），不算错误，进入人工确认；**预测端的 conflict 声明不产生评分豁免**（见 §3.6）。
- 长文本字段（工作内容、项目责任）标注关键信息点，用于字符级比对。
- 现居地与期望工作城市需分别标注到 `city` 与 `expected_city`，不混填。
- 每个可评分字段记录 `status`（`present` / `null` / `conflict` / `not_applicable`）与证据位置（原文 span / 段落编号）；`status=null` 时必须证明评测样本中没有可判定依据，供幻觉判定（§4.3）与匹配依据核对使用。

### 2.5 评测 manifest 与评测 bundle（冻结与复现）

评测必须基于一份冻结的 `evaluation_manifest.json`，记录数据集快照、样本清单、标准答案与运行配置，保证结果可复现：

```json
{
  "bundle_version": "2026-08-07.1",
  "dataset": {
    "name": "简历信息抽取数据",
    "source": "https://aistudio.baidu.com/dataset/detail/40148/file",
    "snapshot_date": "YYYY-MM-DD",
    "version": "下载时页面标注的版本（无版本则记录快照日期）",
    "download_sha256": "…"
  },
  "reference_date": "YYYY-MM-DD",
  "ir_valid_chars_threshold": 200,
  "samples": [
    {
      "sample_id": "eval-001",
      "filename": "resume_001.docx",
      "category": "表格型",
      "format": "docx",
      "layout": "表格型",
      "quality_flags": ["正常"],
      "sha256": "…",
      "split": "holdout",
      "source_sha256": "…",
      "derived_artifact": null
    }
  ],
  "ground_truth": {
    "path": "ground_truth/v1/",
    "sha256": "…",
    "labeler_version": "标注指南 v1"
  },
  "profile_label_set": {
    "path": "profile_labels/v1/",
    "sha256": "…"
  },
  "runtime": {
    "parser_version": "…",
    "llm": {"provider": "…", "model": "…", "api_contract": "…"},
    "prompt_version": "…",
    "schema_version": "…",
    "scorer_version": "…",
    "retry_policy": "评测按 §6 单次重试；生产按 PRD F6 最多自动 2 次"
  }
}
```

- `reference_date`：`years_experience` 等派生字段的计算基准日（见 Schema spec §1.8），评测内固定。
- `ir_valid_chars_threshold`：IR 有效字符下限，**正式冻结为 200**（与 PRD F6 同步，不再「暂定」）。
- `sha256`：样本文件哈希，防止文件被替换后结果失真。
- `source_sha256` / `derived_artifact`：当为格式转换或人为构造的 `.doc` / 文本框样本时，记录原始样本 hash、转换工具版本和产物 hash；不得把转换产物伪装成公开数据集原始文件。
- `ground_truth.sha256` / `profile_label_set.sha256`：标准答案与画像标注子集哈希，防篡改。
- **运行配置冻结**：`runtime` 记录解析器、LLM 模型与契约、提示词、schema、评分器版本；外部模型无法固定版本时，提供录制响应或离线测试替身保证可复跑。
- manifest 一经冻结不允许增删样本或修改标准答案「凑指标」；确需调整时生成新版本 bundle（`bundle_version` 递增）并重新跑基线。
- 所有指标必须基于 manifest 内样本计算，评测脚本读取 manifest，不接受散落的样本文件。

## 3. 字段归一化与匹配规则（评测口径）

本节定义比对前的归一化与匹配算法，确保不同实现得到相同分数。

### 3.1 文本归一化

比对前对预测值与标准答案同时做：

- 去除首尾空白，连续空白折叠为单个空格。
- 全角字母 / 数字转半角。
- 技能与枚举字段比对时统一转小写。
- 日期统一为 `YYYY-MM`；「至今 / present / 今」→ `end` 记为 `null`（在职）。
- 不去除标点（姓名 / 公司 / 院校保留原标点）。

### 3.2 null / 空值处理

- `null`、空字符串、缺失三者等价，均视为「无值」。
- 预测无值 且 标准答案无值 → 正确；该值不产生 TP/FP/FN。
- 预测有值 且 标准答案无值 → 误报（若无简历依据，同时计入幻觉率，见 4.3）。
- 预测无值 且 标准答案有值 → 漏报。
- 数组字段的 `[]` 与 `null` 语义不同（见 Schema spec §1 空值语义）：`[]` 视为「确认无该经历」，与预测 `[]` 匹配为正确；预测 `null`（无法确定）而标准答案为 `[]` 视为漏报（该数组整体缺失）。
- 数组四种组合固定为：`[]/[]` 正确；`null/null` 正确但不计 TP；预测 `[]`、标准 `null` 为误报；预测 `null`、标准 `[]` 为漏报。非空数组按 §3.3 配对后评分。

### 3.3 数组字段匹配（教育 / 工作 / 项目）

- 先按关键字段配对预测项与标准答案项：教育→`school`，工作→`company`，项目→`name`。
- 配对规则：关键字段归一化后精确匹配即配对；无精确匹配时按字符串相似度 ≥ 0.8 配对；每个标准答案项至多配对一次。
- **配对可复现性**：使用全局一对一最大匹配；边权依次为「关键字段精确匹配 > 相似度」，相似度相同按标准项 `start`、预测项原数组 index、标准答案原数组 index 的字典序 tie-break；相似度算法固定为 Jaccard-Token（中文按字符切分），阈值固定为 0.8，并记录版本；关键字段为 `null` 的项不参与配对，逐字段按 `null` 规则计分。
- 配对后逐项比对其余字段（学位 / 职务 / 起止时间等）。
- 未配对的预测项 → 误报；未配对的标准答案项 → 漏报。
- 不要求数组顺序一致。

### 3.4 skills 数组匹配

- `skills` 是无序集合：去重后按 schema spec §3.6 的 canonical dictionary 归一化，不按数组顺序评分。
- 预测集合与标准集合交集为 TP，预测独有项为 FP，标准独有项为 FN；空集合按 §3.2 的 `null/[]` 矩阵处理。

### 3.5 长文本字段比对

- 固定算法为**字符二元组 F1（character bigram，n=2）**：将内容切分为字符二元组**多重集合**（保留重复二元组），计算 `F1 = 2·P·R / (P + R)`。多重集合交集按两集合中相同二元组出现次数的最小值计算。
- 文本长度 < 2 字符时退化为字符级别（unigram）比对；空文本不产生二元组，按 `null` 规则计分。
- 权重见 4.2（长文本权重 0.5，避免主导宏加权）。

### 3.6 conflict 处理

- 只有 **Ground Truth 预先冻结标注的 `conflict` 字段**才从字段级 F1 中排除（不算错误）；预测端自行声明的 `conflict` 不产生豁免，按正常字段比对计分。
- 单独统计「待人工确认」字段数量并报告；另按 §4.5 评估 conflict 检测准确率。
- 每个 `format` / `layout` / `quality_flags` 分组报告 conflict 字段占比；占全部可评分字段 occurrence 超过 20% 的分组不得以 F1 门槛判定通过，需人工复核标注质量与样本真实性。

### 3.7 字段级 F1 的原子单位与 TP/FP/FN（正式冻结）

- **原子单位**：字段 occurrence。普通字段为 1 个 occurrence；数组元素配对后，其每个比对的子字段（如 `work[0].title`）各为 1 个 occurrence。
- **TP / FP / FN 定义**：
  - 普通字段：预测有值且与标准答案一致 → TP；预测有值且标准答案无值 → FP；预测无值而标准答案有值 → FN；预测有值且标准答案有值但不一致 → **FP + FN**。
  - 长文本字段：以字符二元组多重集合计 TP/FP/FN（TP=交集数、FP=预测独有数、FN=标准独有数）。
  - 数组字段：配对成功项按子字段计；未配对预测项按组计 FP，未配对标准项按组计 FN。
- **聚合**：跨全部样本按字段维度汇总 TP/FP/FN 后计算各字段 F1，再按权重宏加权（见 4.2）。不按「每份简历先平均再宏平均」。
- **零分母**：某字段全评测集无 TP+FP+FN（无正例也无比对）时，该字段不参与宏加权（分母剔除），并在报告中显式列出被剔除字段。
- **评分对象**：解析流水线原始输出（人工修正前）的 `candidate.json`；人工修正数据不进入评测输入。

## 4. 评测指标

全部指标由自动评测脚本对「解析输出」与「标准答案」按第 3 节规则比对得出。

### 4.1 解析成功率

```
解析成功率 = 成功完成解析并入库的简历数 / manifest 内全部合格样本数
```

- 目标：≥ 90%（PRD M3）。
- 失败定义：抽取失败、IR 无效字符低于阈值（200）、LLM 结构化调用失败且重试后仍失败。
- **分母口径（正式冻结）**：分母为 manifest 预注册的全部合格样本（含最终失败样本），不得依据运行结果增删样本；样本的 `split` 在构建时冻结，不接受运行后调整。
- **失败样本在字段 F1 中的处理**：流水线级失败样本以该 Schema 全部可评分字段为 `null` 的候选输出计入端到端字段 F1，失败数量与失败原因单独报告；另报告「成功样本条件 F1」用于定位结构化质量，但验收使用端到端 F1，任何失败样本不得被标记为 `conflict` 规避。

### 4.2 结构化字段准确率（字段级 F1，宏加权）

- **普通字段**（姓名、学历、院校等短文本/枚举）：字段级精确匹配（归一化后）；`skills` 作为无序集合按 §3.4 计算。
- **长文本字段**（工作内容、项目责任）：字符二元组多重集合 F1（见 3.4）。
- 原子单位、TP/FP/FN 与聚合规则见 §3.7。

```
字段级 F1 = 2 × Precision × Recall / (Precision + Recall)
宏加权 F1 = Σ(w_i × 字段级 F1_i) / Σ w_i
```

- 目标：≥ 0.85（PRD M3）。
- 权重：普通字段权重 1，长文本字段权重 0.5。
- 仅 Ground Truth 冻结的 `conflict` 字段不计入（见 3.6）。

### 4.3 幻觉率（编造率）

```
幻觉率 = 输出值在简历原文与标准答案中均无依据的字段数 / 输出的非空字段总数
```

- **分母（正式冻结）**：只统计预测输出的非空字段 occurrence；全量输出 `null` 时幻觉率分母为 0，此时幻觉率按 0 处理并单独报告（无编造输出）。
- 目标：观测基线，MVP 阶段不设比例目标，但**任何确认的编造字段 occurrence 都是阻断缺陷**；自动 scorer 发现一条即记录样本与字段明细并返回非零退出码，判定 M3 不合格。
- 判定：预测输出的非空字段对应 Ground Truth 的 `status=null`，且无法通过冻结的 evidence span / quote hash 在 IR 中验证依据，即视为幻觉；证据缺失、引用越界或 hash 不匹配按无依据处理。

### 4.4 人才画像准确率与标注协议

**指标**：

- 固定八维枚举字段：人工抽检分类是否与简历依据一致。
- 目标：抽检准确率 ≥ 85%（参考观测指标，不作为 M3 阻断门槛）。

**标注协议**（数据集不自带八维画像标签，需专门构建标注子集）：

- 从冻结评测集中分层抽样**至少 50 份**简历构成画像标注子集。
- 每份简历由 2 人独立标注八维（职级层级 / 专业深度 / 领域经验 / 影响范围 / 管理能力 / 职业稳定性 / 成长趋势 / 沟通协作）。
- 每个维度的标注必须能在简历中找到依据；无依据时标 `unknown`（画像标注专用取值，与简历 Schema 的 `null` 口径独立），不强行归类。
- 两人不一致时由第三人仲裁或讨论达成一致；记录并报告双人标注一致率（≥ 0.8 为合格标注质量）。
- **口径（正式冻结）**：画像准确率为**参考观测指标**，标注子集未就绪时按观测值报告，不阻断解析 / 搜人两项核心门槛（与 PRD M3 一致）；画像不参与字段级 F1 与搜人 fixture 的硬性门槛。

### 4.5 conflict 检测准确率

```
conflict 检测准确率 = 预测正确标记的 conflict 字段数 / 标准答案冻结的 conflict 字段总数
```

- 目标：观测基线；报告「待人工确认」数量与检测准确率，作为解析器对脏数据敏感度的参考。
- 预测端多余标记的 conflict（标准答案未标记）按正常字段比对计分，不豁免。
- 当 manifest 中没有 Ground Truth conflict 字段时，检测准确率记为 `N/A`，不得以 `0/0` 计入整体平均；同时报告预测端多余 conflict 数量。

### 4.6 分类别门槛

- 按 `format` / `layout` / `quality_flags` 分别报告端到端字段级 F1 与解析成功率。
- 每类的端到端字段级 F1 单独设 ≥ 0.75，解析成功率单独设 ≥ 0.90；整体宏加权仍按 §4.2 的 ≥ 0.85 门槛，防止选择性将某一类难样本标记为 failed。

## 5. 评测流程

```
1. 构建并冻结评测 bundle（样本 + 标准答案 + 画像标注子集 + 运行配置，见 §2.5）
2. 运行解析流水线（上传 → 解析 → 结构化 → 画像），产出人工修正前的原始 candidate.json
3. 脚本按第 3 节规则比对解析输出与标准答案，输出指标
4. 指标不达标 → 定位失败类别（抽取 / 结构化 / 画像）→ 迭代
5. 指标达标 → 冻结该版本，作为回归基线
```

- bundle 冻结后不允许修改标准答案「凑指标」。
- 每次解析代码变更后跑回归，指标回退视为回归缺陷。

## 6. 失败分类与处置

| 失败类别 | 处置 |
|----------|------|
| 抽取失败（双通道均失败 / IR 无效） | 标记 failed，可查看原因并重试；计入成功率分母 |
| 结构化输出校验失败 | 以字段级 `null` 作为本次失败输出；按固定重试策略重试一次；仍失败则整份流水线为 `failed`，计入端到端 F1 与成功率分母 |
| LLM 调用失败 | 降级提示，不损坏已发布数据；重试一次后仍失败整份流水线为 `failed`，以全字段 `null` 计入端到端 F1 |
| 字段矛盾 | 由 Ground Truth 冻结标注 `conflict`，进入人工确认，不计为解析错误 |

## 7. 待确认项

- 各类别最低数量与配额已在本版冻结（§2.2）；四类样本的最终数量与文件清单在构建 bundle 时按数据集实际规模定稿并冻结。
- 数组配对的相似度阈值（当前定 0.8）与相似度算法版本在 bundle 中冻结；如需微调，在开发集上进行并生成新 bundle 版本，不得在冻结评测集上调参。
