## 1. 目标

本节把 PRD 中未收敛的 MVP 目标收口为可验收的表述。

### 1.1 产品定位

AgentKB MVP 面向企业人事部门整体使用，是「AI 招聘工作台」：把简历解析、结构化入库、自然语言搜人与招聘流程推进串成一条闭环，核心价值在「简历解析质量」与「搜人质量」。

### 1.2 目标客户与权限边界

- MVP 目标客户为**企业内部人事部门整体**，不按 HR、招聘专员、人事专员、面试官等岗位拆分业务权限。
- 人事部门内部成员统一使用人才库、搜人、候选人管理和招聘流程功能。
- 业务部门负责人、外部面试官、跨部门协作**不在 MVP 范围内**。
- 「面试官」仅为面试任务上的负责人字段，不产生权限差异。
- 平台底座保留 `owner / admin / member` 账号权限，招聘业务层不新增权限细分。
- **口径澄清**：「不按岗位拆分权限」指**招聘业务层**（搜人、查看候选人、上传、指派、状态流转等）；底座的模型配置、职位编辑/关闭、入职员工库查询等 admin/member 差异属于**平台基础管理权限**，不属于岗位级招聘权限，两者不冲突（对齐 PRD §4.2 第 4 条）。

### 1.3 核心价值优先级与分期

P0 阶段优先验证两项能力，招聘流程协同作为支撑闭环，不平级：

1. **简历解析质量**：能否准确理解企业简历，结构化字段准确、不编造。
2. **搜人质量**：人事部门能否通过自然语言找到符合条件的人。

对应 PRD §7.3 的分期：

- **P0-核心**（F6/F7/F8/F9/F10/F12）：解析 + 搜人 + 候选人管理 + 查重 + 职位的核心验证链路，须先通过两份评测 spec 的量化门槛。
- **P0-支撑**（F11/F13/F14/F15）：人才库查询、招聘管道、待面试表、面试反馈、三池模型，核心链路达标后交付，按功能完整性验收，不作核心价值判断依据。

### 1.4 模型供应商治理

MVP 不重点评估模型供应商合规与数据出境治理。客户自行配置模型服务地址与 Key 并承担费用，平台负责：

- Key 加密存储。
- 模型调用失败降级与提示。
- 调用失败不损坏简历数据。

## 2. 功能范围

### 2.1 首期闭环（核心验证链路，P0-核心）

```
上传简历 → 解析结构化 → 人工查看结果 → 建立索引
        → 自然语言搜人 → 返回候选人卡片与匹配依据
```

含：简历解析（F6）、对话式搜人（F7）、候选人管理（F8）、查重来源（F12）、场景权限（F9）、职位管理简化版（F10，支撑「按岗位搜索」）。

### 2.2 支撑能力（P0-支撑）

- 人才库自然语言查询（F11）、招聘管道与待面试表（F13）、面试安排与反馈（F14，含 AI 总结）、候选人时间线、三池模型（F15）。

### 2.3 明确不做（MVP）

- 业务部门 / 外部面试官接入。
- 招聘业务层细粒度权限。
- 模型供应商合规治理、数据出境限制。
- 其余五个场景（客服 / 财务 / 法务 / 运营 / 售前）的编排实现。

## 3. 验收口径

### 3.1 指标定义

| 指标 | 定义 | 目标 |
|------|------|------|
| 简历解析成功率 | 成功完成解析并入库的简历 / manifest 内全部合格样本（含失败样本，见解析评测 spec §4.1） | ≥ 90% |
| 结构化字段准确率 | 端到端字段级 F1（宏加权），按解析评测 spec §3.7/§4.2 的原子单位与聚合规则，流水线失败样本以全字段 `null` 计入 | ≥ 0.85 |
| 结构化字段分类别门槛 | 按 format / layout / quality_flags 分类别的端到端字段级 F1 | 每类 ≥ 0.75，成功率 ≥ 0.90 |
| 人工修正率 | 被人工修正过字段的候选人 / 已入库候选人 | 观测基线，MVP 不设硬性目标 |
| 核心候选搜索 Precision@10 | 仅 `core_candidate_search` / `pool_history_search` 候选列表查询计分（搜人评测 spec §3.2） | ≥ 0.80 |
| 搜人每类候选查询 Precision@10 | 按硬门槛候选查询族分别计算 | 每类 ≥ 0.70 |
| 搜人数量满足率 | `requested_count != null` 的候选列表查询，返回唯一有效候选数 ≥ min(requested_count, available_relevant_count)（搜人评测 spec §3.4） | ≥ 0.90 |
| 统计查询准确率 | 仅 `statistics` 查询族使用统计结果与标准答案比较（搜人评测 spec §3.7） | ≥ 0.90 |
| 搜索条件理解准确率 | 按候选查询族，条件 AST 与标准条件完全一致（搜人评测 spec §3.1） | ≥ 0.85 |
| 搜人 Recall@10 | 候选列表前 10 命中 relevant / available_relevant_count（搜人评测 spec §3.3） | 观测基线 |
| 无结果准确率 | 仅 `no_result` 预期响应族使用（搜人评测 spec §3.5） | ≥ 0.90 |
| 多轮追问收敛准确率 | 追问轮次中正确收敛的比例（搜人评测 spec §3.6） | 观测基线，MVP 不设硬性目标 |
| 非搜索意图准确率 | `non_search` 意图识别及无业务副作用（搜人评测 spec §3.8；允许脱敏只读审计事件） | ≥ 0.90，且零业务副作用 |
| 人才画像抽检准确率 | 固定八维枚举抽检准确率（解析评测 spec §4.4） | 参考观测指标，≥ 85% 不阻断 |

### 3.2 验收前提

- 解析与搜索指标的评测使用指定的合成公开数据集快照与冻结评测 bundle，评测规则见对应 spec；M4 先验收服务端 `pool_scope` ACL，M5 再验收完整池流转。
- 指标由自动评测脚本出具（以非零退出码阻断 CI），不依赖人工口头认定。
- 画像准确率为参考观测指标，标注子集未就绪时不阻断解析 / 搜人两项核心门槛；画像依赖查询不进入 M4 核心硬门槛，改由搜人 spec §3.8 单独报告。

### 3.3 功能验收矩阵（P0-核心 / P0-支撑功能完整性）

量化指标之外的验收用例，按功能域逐项验收（自动化 / 集成测试 + 必要的 UI E2E）：

| 功能域 | 验收用例 |
|--------|----------|
| 文件上传安全 | 扩展名与文件签名不匹配拒收；加密 / 宏 / 嵌入对象 / 压缩炸弹默认拒收；恶意文件扫描、解压后 ≤100MB、XML 深度 ≤100、对象 ≤20、CPU ≤60s、内存 ≤1GB、临时磁盘 ≤500MB；worker 重启后临时目录清理 |
| 批量上传与幂等 | 单批 ≤100 份、≤20MB；重复提交同一 upload 不产生重复记录，显式重解析生成新 run；CSV/JSON 按 `row_hash` 仅重试失败行；worker 重启后任务不重复执行 |
| 解析失败与重试 | 失败可查看原因并单独重试；重试以 run_id 幂等，不重复扣费、不覆盖已发布版本 |
| 查重与合并 | 姓名 +（phone 或 email）命中提示合并；合并后保留历史简历与 revision；跨池命中提示池归属与历史记录 |
| 人工修正与重解析 | 修正后重新解析不覆盖 override；数组字段修正；并发修正冲突提示 HR 选择 |
| 软删除与恢复 | `active → deleted（30 天可恢复）→ purged`；软删除从检索移除但仍参与查重提示；恢复原子重建索引；硬删除级联擦除并保留 tombstone |
| 权限越权（负向） | 跨租户访问资源统一 404；owner 继承 admin；member 可上传/创建职位但不能编辑/关闭职位；入职员工库仅 owner/admin；superuser 默认无候选人原文/PII；历史条件先按 ACL 过滤；服务端拒绝伪造池范围参数 |
| 职位与 HC | 职位创建/关闭权限；并发加入与发 offer 不得超卖；`hc_reserved=offer`、`hc_filled=hired`；关闭职位不可新增指派，既有流程可完成或转 `closed_by_job`；同名职位必须按 job_id 确认 |
| 指派状态机 | 状态流转符合 PRD F13 机器枚举；任意非终态可淘汰且原因必填；`hired/offer_rejected/rejected/closed_after_hire/closed_by_job` 终态不可重开；状态变更与时间线、池流转一致 |
| 人才池流转 | 候选人锁下原子聚合：`hired` 优先，其次进行中为 `active`，否则淘汰/拒绝为 `rejected`；入职原子关闭余下指派；`hired` 不可重指派，`rejected` 可回 `active`；默认搜索不跨池混入 |
| 面试反馈闭环 | 结构化反馈必填校验；超 48 小时站内待办提醒；反馈 AI 总结可编辑、保留原始评语 |
| 时间线一致性 | 池流转、状态流转、人工修正、沟通备注均留痕，时间倒序一致 |

## 4. 风险与决策记录

| 事项 | 结论 |
|------|------|
| 目标客户 | 人事部门整体，不做岗位级权限 |
| 核心优先级 | 解析质量 > 搜人质量 > 流程协同 |
| 交付分期 | P0-核心先过量化门槛，P0-支撑按功能完整性验收（对齐 PRD §7.3） |
| 模型供应商治理 | MVP 不评估，客户自担 |
| 数据来源 | 合成公开数据集，不把原始个人信息写入文档 |
